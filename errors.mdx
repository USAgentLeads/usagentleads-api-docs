---
title: "Errors and retries"
---
| Status | Action |
| --- | --- |
| 400 | Correct validation errors; unsupported filters and extra identity fields are rejected |
| 401 / 403 | Check credentials, key expiry and API plan |
| 402 | Insufficient credits; no partial acquisition |
| 409 | Check credit cap, changed idempotency payload, cursor mismatch or export readiness |
| 410 | Cursor, catalog snapshot or stored result expired |
| 429 | Wait at least Retry-After; obey account, IP, concurrency and monthly quotas |
| 503 / network timeout | Retry with the exact saved key and payload, or recover the request |

Errors include a machine code and message; legacy authentication/quota responses may use a string `error`.

Do not treat a network failure as proof that no charge occurred. `GET /api/v3/requests/{idempotency-key}` retrieves the account-scoped receipt for 30 days. An unknown receipt returns 404; if the first request may still be running, retry the original request. Expired keys return 410 and cannot be reused. Use a new key only for a deliberately new operation.
