---
title: "Rate limits"
---
All public API operations are limited, including calls that spend no credits.

| Limit | Scope |
| --- | --- |
| 60 authenticated requests/minute | Shared account across keys, REST v3 and hosted MCP |
| 5 concurrent v3 searches/lookups/discovery/export selections | Account |
| 5 export creation attempts/minute | Account, within the 60/minute allowance |
| 2 queued exports | Account |
| 60 public coverage/location requests/minute | IP |
| 120 authentication attempts/minute | IP, before API-key lookup |
| 100 records per synchronous page/lookup | Request |
| 5,000 records per export | Job |

Responses include `X-RateLimit-Limit`, `X-RateLimit-Remaining`, and `X-RateLimit-Reset` (a conservative Unix retry time). Authenticated successful responses also include monthly quota headers. HTTP 429 includes `Retry-After` in seconds. Wait, then retry with the same idempotency key and payload. Use exponential backoff with jitter for repeated 429/503 responses.

Rate-limit rejection happens before contact acquisition. The limiter fails closed during an outage. Crashed concurrency slots expire after five minutes. Export generation shares the existing global one-generation-at-a-time database limit.

Polling and MCP initialization/tool listing consume request allowance. Poll export status sparingly. Monthly quotas reset on the first day of the next UTC month.
